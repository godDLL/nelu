Nelu 0.2.1 Reference Manual

Nelua-in-Nim 0.2.1 (clean-room reimplementation) · semver 0.2.1 · Lua-shaped, statically typed, AOT to C · compiled by gcc
How to read this manual. Three markings recur throughout: parity matches the oracle 0.2.0-dev behaviour, Nelu ext is a clean-room addition beyond 0.2.0, queued is designed but not yet implemented. A fourth mark, bug, flags a known open compiler defect in the tree this was written against (see Appendix). A reference manual documents the language specification; the current compiler build has known bugs and not every example below is known to compile today.

1. What is Nelu

Nelu is a clean-room reimplementation of the Nelua language: Nelua-in-Nim. The compiler is written in Nim, emits C, and compiles that C to a native binary with gcc. Two artifacts ship:

  • nelu — the Nelu compiler (Nim -> C -> native).
  • nelu-lua — a bundled standalone Lua 5.4.3 interpreter, built from C, with the Nelua init layer and the lpeglabel module.

One-line pitch. Lua-shaped syntax, statically typed, that compiles to C and then to native code: Lua ergonomics with C performance and direct, ergonomic access to C functions and headers.

Build. The Makefile drives both toolchains:

# The Nelu compiler (Nim -> C -> native).
make nelu            # nim c -d:release --path:src -o:nelu src/main.nim

# The bundled Lua interpreter (C).
make nelu-lua        # gcc ... onelua.c + src/*.c + lpeglabel/*.c -o nelu-lua

make all             # both
make test            # ./nelu-lua spec/init.lua

Version output: nelu --version -> Nelua-in-Nim 0.2.1 (clean-room reimplementation); nelu --semver -> 0.2.1.

2. First program

You do not write a main function. Top-level statements become the entry point; the compiler emits int nelua_main(int, char**). print is a builtin.

-- hello.nelua
print 'Hello world!'

Build and run (the -L <dir> flag is the library search path for require; require 'name' resolves to <dir>/name.nelua):

nelu -L lib -o hello hello.nelua
./hello
# Hello world!

The compiler is AOT-only: nelua source -> C source -> native binary. There is no interpreter and no way to load runtime-generated code. print writes to stdout and takes multiple arguments separated by tabs:

print(1, 2)     -- 1\t2

3. What stays the same from Lua

You can read most of a Nelua program as Lua. These are byte-for-byte identical:

  • Comments. -- line, --[[ ... ]], and --[=[ ... ]=] (long-bracket comments with any number of =; opening and closing brackets match).
  • String literals. single/double quoted; the same escape sequences (\n, \t, \u{03C0}, \x41, \65, \z whitespace-trim, \ line continuation). Strings are immutable, contiguous, pointer+size, null-terminated for C.
  • Number literals. decimal, binary 0b1010, hex 0xff, char 'A'_u8, scientific 1.2e-100, hex-float 0x1.921FB54442D18p+1.
  • Boolean and nil. true, false, nil.
  • Operators. + - * / // /// % %%% ^ .. and or not == ~= < > <= >= # (length/sizeof), plus the bitwise additions | & ~ << >> >>> (logical shift), >>> arithmetic right shift, ~a bitwise NOT, $a deref, &a address-of.
  • Control flow shapes. if / elseif / else, while, repeat ... until, numeric for, for ... in (iterator), break, continue, do ... end.
  • Multiple assignment. local a, b = 1, 2; b, a = a, b (safe swap).
  • Functions. function f(a, b) ... end, anonymous function(x) ... end, first-class values, recursion, multiple returns.

5. Branching and flow constructs

5.1 if / elseif / else

if x then
  -- one true branch
elseif y then
  -- second true branch
else
  -- everything else
end

5.2 while / repeat-until

while x do ... end
repeat
  ... body ...
until x   -- test is at the bottom; runs at least once

5.3 Numeric for / iterator for

for i : integer = 0, N do ... end   -- inclusive start, exclusive end
for k, v in iter do ... end           -- iterator form

5.4 break / continue / do / return

do ... end          -- explicit block scope
break               -- exit enclosing loop
continue           -- next iteration Nelu ext
return a, b        -- multiple returns

5.5 defer / <close> / error / panic

defer cleanup()        -- run at scope exit, reverse order, before return/break/continue
local r: Resource <close>   -- run r.__close() when r leaves scope
error('boom')          -- runtime abort (SIGABRT)
panic('boom')          -- runtime abort

5.6 Queued: try/catch/finally, match/cond

Not implemented. The queued Nelu extensions for exception handling (try ... catch ... finally) and pattern matching (match ... case ... else, cond) are designed but not landed. On the current tree they are syntax errors. Parity-level building blocks that do exist: the switch/case/else statement, the fallthrough keyword, and the panic/defer/<close> primitives.

6. The type system

6.1 Declarations

local b = false                 -- deduced boolean
local pi: number = 3.14           -- explicit annotation
local N <comptime> = 8            -- compile-time constant, usable as array size
local x <const> = 5             -- runtime-once immutable
local a: auto = 1                -- type inferred from first assignment
global g : integer = 1            -- top-scope symbol visible to other files
local p: *integer <noinit>        -- skip zero-initialisation

A declared-but-uninitialized variable is always zero-initialised (false/0). This is the "Zero Is Initialization" idiom; there are no constructors/destructors. Disable it per-variable with <noinit>.

6.2 Composite types

DeclarationC shape
record { x: float64, y: float64 } (also @record{...})struct { double x; double y; }
union { i: int64, f: float64 } (also @union{...})union
enum { A=0, B, C } (@enum rejected)enum (first value must be initialised)
array(T, N) / [N]T (annotation only)T arr[N], fixed size, passed by value
*T / pointer(T) (@pointer rejected)pointer to T
span(T)fat pointer: *[0]T + size, runtime bounds-checked
function(a: int): int (@function rejected)function pointer (stores callbacks)
facultative(T) (annotation only; T? queued)optional
A | B | Cvariant (union of types)

Record literals use (@Person){ name = "Mark", age = 20 } (typed) or ordered-field { "Mark", 20 }. A colon method function T:m(...) receives self as *T implicitly; method calls auto-reference/dereference the receiver. #SomeType on a type returns its size in bytes.

6.3 The @ prefix rules

The @ prefix is accepted on record and union but rejected on enum, pointer, and function (those take bare keywords). Bracket [N]T works in annotation position only, not as a standalone expression.

6.4 nil, any, facultative

  • nil is not the universal "no value" it is in Lua; there is a niltype for unions/optionals.
  • nilptr is a separate literal (pointer-sized nil, its own AST node). It is the one value assignable to any pointer type: local p: *integer = nilptr. local p: *integer = nil is a niltype -> pointer error.
  • any Nelu ext: phase 1 rejects deduced any (parity with the oracle); phase 2 (landed) makes it a tagged union (nlany) with runtime construction/dispatch helpers.
  • facultative(T) cannot be used in return position; a function that may return "no value" returns a boolean signal plus the value.

7. local is not hoisted

This is the key Lua divergence. A local name enters scope at the line where it is declared - unlike Lua, where the whole enclosing block sees it.

-- WRONG (Lua-hoisted thinking): spins forever at 100% CPU, no error.
while true do
  pos = advance(s, pos)              -- uses the OUTER pos
  local ok, key, pos = parse(s, pos) -- declares a NEW local pos
end

-- RIGHT: give the returned position a different name.
while true do
  local ok, key, nextpos = parse(s, pos)
  pos = nextpos
end

8. Metaprogramming: the compile-time Lua preprocessor

Nelua embeds a full Lua preprocessor. Between its statements, arbitrary Lua runs at compile time. Lines starting with ## and blocks between ##[[ ... ]] are Lua code, evaluated at compile time and persistent across modules (declare helpers local so they do not leak).

8.1 Splice tokens

  • #[expr]# - replace the token with a Nelua value/AST produced by the preprocessor.
  • #|name| # - replace with an identifier produced by the preprocessor.
  • #[node]# - emit an AST-node expression; inject_astnode(node) injects a statement at the call site.

8.2 Macros and generics

-- preprocessor macro
## local function repeat_n(n, body) ... ## end
-- called as #[macro]#(...); expr_macro for expression position

-- generics: preprocessor functions rendered with the generalize macro
local FixedStackArray: type = #[make_FixedStackArray]#

vector, sequence, and span are built this way. Generics are memoized per argument set - like C++ templates.

3.3 Concepts, assertions, C emission

  • Concepts decide at compile time whether an argument type matches, returning true, a type to infer to, or (false, 'error message'). facultative(T), overload(t1, t2, ...) are shortcuts. Type properties live on attr.type: is_scalar, is_stringy, is_integral, is_float, is_pointer, is_array, is_record, is_niltype, plus custom flags.
  • static_assert(cond, fmt, ...) and static_error(fmt, ...).
  • You can iterate and even modify already-processed symbols (Weekends.value.fields, Person.value:add_field('age', ...)).
  • ## cdefine 'X' emits a #define; ## linklib 'm' passes -lm; ## cflags / ## ldflags add flags; ## cemit / cemitdecl / cemitdef inject raw C.
  • Share preprocessor helpers from standalone .lua modules: ## local foo = require "foo" (set LUA_PATH if needed).

9.3 Varargs, pointers, the -lm gotcha

Direct calls map 1:1. ...: cvarargs is the varargs parameter; the compiler specializes the call per argument set. For the v* family you pass a cvalist as an ordinary parameter - it is never unpacked from ...:

local function cprintf(fmt: cstring, ...: cvarargs): cint
  local ap: cvalist <noinit>
  C.va_start(ap, fmt)
  local n = C.vprintf(fmt, ap)
  C.va_end(ap)
  return n
end

The -lm gotcha. Nelua does not add -lm itself. Using math.sqrt (or any libm function) without declaring the math library produces a linker error: undefined reference to 'sqrt'. Fix it in source with ## linklib 'm' (or pass -lm on the command line).

9.4 Reading the generated C

The compiler emits one readable C file with sections: declarations, definitions, and per-function bodies. The entry point is int nelua_main(int, char**). Use -c/--code to emit C and stop, and --print-code to print the generated code.

10. Standard library

All libraries use require 'name'. Builtins (require, print, panic, error, assert, check, likely, unlikely, _VERSION) are not required. Method names below are read from the lib/ source.

10.1 arg

Global arg: sequence(string, GeneralAllocator) of command-line arguments. Index 0 is usually the executable name; indices 1..#arg are the arguments.

10.2 builtins

Documentation-only; must never be required. Documents the predeclared builtins: require, print, panic, error, assert, check, likely, unlikely, _VERSION.

10.3 coroutine Nelu ext

A Nelu addition (the oracle 0.2.0-dev has no coroutine module). Handle type lowering to minicoro fibers, C-backend only. Methods: create, destroy, push, pop, isyieldable, resume, spawn, yield, running, status. No varargs on yield/resume - values move via push/pop with compile-time-known types. coroutine.wrap does not exist.

10.4 errorhandling

Provides pcall, xpcall, plus the panic machinery (raise_impl, NELUA_TRAP, NELUA_UBSAN_UNREACHABLE). Exports: panic, error, assert, pcall, xpcall, abort, exit.

10.5 filestream

11. The embedded Lua engine (preprocessor + nelu-lua)

The preprocessor IS Lua. You cannot understand Nelua metaprogramming without understanding that the compile-time preprocessor is a Lua engine embedded in the compiler. The ## lines and ##[[ ... ]] blocks between statements are arbitrary Lua evaluated at compile time. Every metaprogramming surface - #[expr]#, #|name| #, #[node]#, inject_astnode, macros, generalize/generics, concepts, static_assert/static_error - is this embedded Lua speaking. There is no separate "metaprogramming language"; there is only Lua, running inside the compiler before it emits C.

11.1 Two surfaces of the same Lua engine, one implementation

There is one Lua 5.4.3 base, and it appears in two places:

  • Compile time. The compiler runs Lua while analyzing your program, via src/luaengine.nim and the build-time Lua source in lualib/nelua/. This is the preprocessor: it evaluates your ## blocks and splice tokens, and it exposes the Nelua AST/attr APIs to you (context.rootscope.symbols, attr.type, the generalize/concept/overload helpers).
  • Standalone. nelu-lua is the standalone build of that same Lua 5.4.3, from C: src/lua/onelua.c plus src/*.c plus src/lpeglabel/*.c, linked with the Nelua init layer (src/luainit.c, src/luainit.h, src/luainit.lua). It is used for running Lua scripts and for running the spec suite.

The relationship: same Lua 5.4.3 base; the preprocessor uses the compiler's embedded Lua with the Nelua AST/attr APIs exposed to it; nelu-lua is the standalone build of that same Lua plus the Nelua init layer and lpeglabel.

11.2 What the preprocessor Lua can and cannot see

  • Persists across modules. ## state survives require boundaries. Declare helpers local so they do not leak into other modules.
  • require "foo" from a standalone .lua module works inside ## blocks - set LUA_PATH if the module is not on the default path.
  • Standard Lua functions are available inside ## blocks: select, string, table, math, io, and the rest of the Lua 5.4.3 standard library.
  • The boundary. Runtime Nelua code cannot load runtime-generated code - compilation is AOT only. All code generation happens at compile time, through the preprocessor. This is the one place where the embedded Lua is not a general-purpose runtime: it is a compile-time tool, and its output is frozen into the C that gcc compiles.

11.3 Building and running nelu-lua

nelu-lua is a bundled standalone Lua 5.4.3 interpreter, built from C:

make nelu-lua     # gcc -O2 -fno-plt -flto ... -o nelu-lua -lm -ldl

./nelu-lua -v reports Lua 5.4.3 Copyright (C) 1994-2021 Lua.org, PUC-Rio. Verified: require "lpeglabel" loads cleanly.

  • Run Lua scripts directly: ./nelu-lua script.lua, or nelu --script script.lua (the --script flag runs a Lua file instead of compiling nelua).
  • Run the spec/test suite: make test -> ./nelu-lua spec/init.lua.

11.4 How nelu-lua differs from stock Lua 5.4.3

  • The Nelua init layer (luainit.c/h/lua) - the bootstrap that opens the Nelua-specific libraries and makes this interpreter the runtime for the compiler and its test suite.
  • The lpeglabel module - a labeled-PG variant of LPeg, included in the build (src/lpeglabel/*.c).

11.5 Running the test suite

make test          # builds nelu-lua if needed, then runs ./nelu-lua spec/init.lua
make test-quick    # lester quiet + stop-on-fail

spec/ contains the spec files: init.lua, aster_spec.lua, bn_spec.lua, cgenerator_spec.lua, except_spec.lua, luagenerator_spec.lua, pegger_spec.lua, preprocessor_spec.lua, runner_spec.lua, stdlib_spec.lua, ...

14.1 Type grammar (infix)

array(T, N) / [N]T (annotation only) array · *T / pointer(T) pointer · span(T) slice · record {…} / union {…} (the @ prefix also works on these two) · enum {…} (@enum rejected) · function(a: T, …): R function pointer (@function rejected) · facultative(T) optional (T? queued) · A | B | C variant · type is the meta-type.

14.2 Attributes (postfix on declarations)

<cimport>, <cimport 'name'>, <cinclude '...'>, <cexport>, <cexport, codename '...'>, <nodecl>, <inline>, <alwaysinline>, <noinline>, <nosideeffect>, <noinit>, <const>, <comptime>, <close>, <align N>, <packed>, <native>, <unsafe>.

14.3 @ metaprogramming tokens

#[expr]# value/AST replacement · #|name| # name replacement · #[node]# AST-node expression · inject_astnode(node) statement injection · generalize for generics · concept(...) / facultative(...) / overload(...) for specialization.

14.4 Builtins

require, print, panic, error, assert, check, likely, unlikely, _VERSION, type, next, pairs, ipairs, sizeof/#, collectgarbage. tonumber, tostring, and tointeger are not builtins - they are global functions defined in lib/string.nelua and need require "string". select is only a standard Lua function available inside ## preprocessor blocks.

15.4 Verified failing on this tree (open compiler defects)

Honesty note. The current tree does not compile most non-trivial programs. These were confirmed by probe, not assumed:
  • Typed record literals mis-lower. The typed literal form (@T){ ... } emits C using an empty struct nlrec0 instead of the record's own type, so gcc rejects it ('struct nlrec0' has no member named 'x'). This is the form used in the manual's record examples; it is tracked as examples/cover/record-literal-typed.nelua (DIFF until fixed). The untyped ordered literal { x = 1, y = "a" } assigned to an annotated local is NOT affected -- examples/cover/record-type.nelua MATCHes the oracle. Probes: tmp/probe_core.nelua, tmp/probe_rec2.nelua, tmp/probe_rec3.nelua, tmp/probe_rec4.nelua, tmp/v_rec.nelua.
  • enum crashes the compiler (SIGSEGV). Probe: tmp/probe_enum.nelua.
  • span emits broken C (static (double[4])* ...). Probe: tmp/probe_span.nelua.
  • The entire stdlib fails to analyze. Root causes: lib/hash.nelua:73:51: error: unexpected token (affects most modules transitively), lib/iterators.nelua preprocessor error (global 'impl_ipairs_next' is not callable), and parse errors in lib/traits.nelua, lib/builtins.nelua, lib/errorhandling.nelua, lib/detail/xoshiro256.nelua. Consequently require 'C.stdio' and every require 'X' fail. Probes: tmp/probe_*.nelua for each module.

These are compiler defects in the tree this was written against, not specification statements. A reference manual documents the language; the reader should verify against their own build. The verification bar for Nelu work is NELU-2K.md section 3 and plan/GATES.md.

15.5 What was deliberately not claimed as verified

  • Anything marked queued (tables, try/catch/finally, match/cond, generators) - designed, not implemented.
  • The coroutine module's C lowering - NELU-2K section 1.1 states it is "not yet wired into cgen.nim"; my probe confirms the module does not compile end-to-end on this tree.
  • Metamethod M3 (__call) and M4 (__index) parity - NELU-2K section 1.7 records M3 as still printing (null) and M4 as unblocked but not re-probed.
  • Record/union/enum/span end-to-end compilation - see 15.4.
